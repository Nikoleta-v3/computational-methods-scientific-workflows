## Exercise: Complete research workflow

In this exercise, you will create a small research workflow from start to
finish.

The goal is not to produce a major scientific result. The goal is to practise
the workflow: choosing a dataset, organising an analysis repository, generating
figures and tables, writing a short paper, and using `git` and GitHub to track
the work.

By the end, another person should be able to open your repositories, understand
what you did, and rerun the main analysis.

## Choose a dataset

Choose a dataset that is small enough to analyse during the exercise.

Good sources include:

- the seaborn example datasets:
  <https://github.com/mwaskom/seaborn-data>
- the same datasets collected on Kaggle:
  <https://www.kaggle.com/datasets/abdoomoh/all-seaborn-built-in-datasets>
- another public dataset from Kaggle or a similar data source


## Create two repositories

Create two separate GitHub repositories:

1. an analysis repository
2. a paper repository

They can be public or private.

## Analysis repository

The analysis repository contains the code and supporting files needed to
reproduce the results.

A suitable structure might look like this:

```text
analysis-project/
+-- README.md
+-- LICENSE
+-- .gitignore
+-- data/
|   +-- README.md
+-- scripts/
|   +-- prepare_data.py
|   +-- plot_figures.py
|   +-- make_tables.py
+-- figures/
+-- tables/
```

You can adapt this structure to your project. The important point is that the
repository should be self-explanatory.

The analysis should be reproducible. I should be able to clone the repository,
install the required packages, run the scripts, and regenerate the main outputs.

## Paper repository

The paper repository contains a short `LaTeX` document describing the analysis.

A suitable structure might look like this:

```text
paper-project/
+-- README.md
+-- paper/
|   +-- main.tex
|   +-- references.bib
+-- figures/
+-- tables/
```

The paper should be between 1 and 5 pages. It does not need to be a complete
journal article, but it should read like a small scientific report.

## Git and GitHub workflow

Use `git` throughout the exercise. Do not wait until the end to make one large
commit.

The [`git` cheat sheet]({{ site.baseurl }}/git_cheatsheet/)
provides a quick reference for the commands used throughout the course.

## What to submit

Submit links to both GitHub repositories:

1. the analysis repository
2. the paper repository

If one of the repositories is private, make sure access is granted before
submission.

## Checklist

Before submitting, check:

- The analysis repository has a clear README.
- The dataset source is documented.
- The analysis can be rerun from the instructions.
- At least one figure is generated by code.
- At least one table is generated by code.
- The paper repository contains a LaTeX manuscript.
- The manuscript is 1 to 5 pages.
- Figures and tables are referenced with LaTeX labels.
- Captions explain what the reader should notice.
- Both repositories have meaningful git history.

The final result should show the complete research workflow: data, code,
outputs, writing, and version control connected in a way that another person
can understand.
